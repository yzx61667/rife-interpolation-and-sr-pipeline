# Build and run

This repository contains no model weights or engine binaries. The commands below
assume you obtained models you are allowed to use and installed the NVIDIA
runtime.

## Requirements (tested versions)

- Windows 10/11, NVIDIA RTX GPU (tested: RTX 4060 Laptop 8GB)
- NVIDIA driver with TensorRT 10.13.3.9 / CUDA 12.x
- Python 3.13
- `numpy`, `onnx`, `onnx-graphsurgeon`
- Optional DirectML fallback: `onnxruntime-directml` 1.24.x
- FFmpeg with `hevc_nvenc`
- TensorRT Python wheel / NVIDIA TensorRT runtime (not pip-installable as a
  redistributable in this repo)

```bat
python -m pip install -r requirements.txt
```

`tensorrt` is intentionally not in `requirements.txt`; install NVIDIA's matching
TensorRT package and make sure its DLLs are on `PATH` or next to Python.

## 1. Generate the tiny I/O graphs

```bat
python python\make_sr_io_onnx.py python\engines
python python\make_u8cast_onnx.py python\engines\rgb_u8cast.onnx
```

This produces:

- `sr_pre_u8hwc_to_f32chw.onnx`
- `sr_post_f32chw_to_u8hwc.onnx`
- `rgb_u8cast.onnx`

## 2. Build the main SR engine

For a static 1080p engine (recommended for 1080p sources):

```bat
python python\build_engine.py ^
  --model path\to\ani4k2.onnx ^
  --engine python\engines\ani4k2_static1080_fp16.engine ^
  --min 2 3 1080 1920 ^
  --opt 2 3 1080 1920 ^
  --max 2 3 1080 1920
```

For an 1080p source with batch 1 instead, use `1` in all three profiles. The
engine profile must match the host's `--batch`.

## 3. Build the GPU-I/O engines

The pre engine input is `(N,H,W,3)` uint8; the post input is `(N,3,H,W)`
float32. Build profiles must match those layouts:

```bat
python python\build_engine.py ^
  --model python\engines\sr_pre_u8hwc_to_f32chw.onnx ^
  --engine python\engines\sr_pre_u8hwc_to_f32chw.engine ^
  --min 1 1080 1920 3 --opt 2 1080 1920 3 --max 2 1088 1920 3

python python\build_engine.py ^
  --model python\engines\sr_post_f32chw_to_u8hwc.onnx ^
  --engine python\engines\sr_post_f32chw_to_u8hwc.engine ^
  --min 1 3 2160 3840 --opt 2 3 2160 3840 --max 2 3 2176 3840
```

The SR host looks for these two files **next to the main engine** (the same
directory as `--engine`). If they are missing or shape-incompatible it falls
back to the legacy NumPy path.

Build the RIFE cast engine:

```bat
python python\build_engine.py ^
  --model python\engines\rgb_u8cast.onnx ^
  --engine python\engines\rgb_u8cast.engine ^
  --min 1 3 1080 1920 --opt 1 3 2160 3840 --max 1 3 2176 3840
```

The RIFE host loads `rgb_u8cast.engine` from its `engines` directory (next to
`trt_engine.py`); copy it there if you keep the main engines elsewhere.

## 4. Build the RIFE engine

Build a RIFE 4.7 TensorRT engine from its ONNX with a static profile matching
the source resolution. `rife_trt_host.py` expects the input tensor layout
`1 x 7 x H x W`; for 1080p use:

```bat
python python\build_engine.py ^
  --model path\to\rife47.onnx ^
  --engine python\engines\rife_v4.7_1920x1080.engine ^
  --min 1 7 1080 1920 --opt 1 7 1080 1920 --max 1 7 1080 1920
```

If the RIFE ONNX has a different input name/shape, adapt the build profile to
its input; the host reads the engine's input tensor at runtime.

## 5. Run the standalone sample

```bat
python python\sample_b2.py ^
  --ffmpeg C:\tools\ffmpeg.exe ^
  --python C:\Python313\python.exe ^
  --src D:\videos\clip.mp4 ^
  --out D:\videos\clip_b2_4k.mp4 ^
  --rife-engine python\engines\rife_v4.7_1920x1080.engine ^
  --sr-engine python\engines\ani4k2_static1080_fp16.engine ^
  --width 1920 --height 1080 ^
  --out-fps 48000/1001 ^
  --sr-workers 2 --sr-batch 2
```

Add `--no-repeat` for the legacy raw path. With repeat enabled, both hosts get
the protocol flags automatically. The sample uses OS pipes and does not include
the Dart relay.

## 6. App integration

The `app/` files are reference copies from the Kazumi-Rife fork, not a standalone
Flutter project. Apply them to a Kazumi-Rife/Kazumi source tree:

- `app/lib/services/sr/sr_pipeline.dart` — B2 streaming chain, correctness fixes,
  repeat flags.
- `app/lib/services/sr/sr_engine_service.dart` — `trtEngineFor(w,h)`, static
  engine selection, auxiliary-engine exclusion.
- `app/tool/bench_b2.dart` — Dart-relay benchmark; it requires the app's
  `assets/sr` layout and a source clip.

Environment switches used by the app:

- `KAZUMI_SR_REPEAT_PROTOCOL=0` disables repeat on both hosts.
- `KAZUMI_SR_STATIC_ENGINE=0` forces the dynamic SR engine in the sample/bench
  helpers that support it.

## 7. Validate

- Decode the output and confirm the expected frame count:
  - 3-minute source with passthrough: 4317 input → 8633 output;
  - 10-second clip: 242 input → 483 output.
- Confirm `hvc1`, AAC, 4K, 47.95 fps.
- Check `trt_host` stderr for `io gpu-io` (not `legacy-f32`) and the
  `units/normal/repeat_units` counts.
- Cool the GPU before timing; see `benchmarks.md`.
